# Gymacro — сайт gymacro.ru

Next.js 15 (App Router), контент статей из WordPress, календарь соревнований подтягивается с сайта ФГР при сборке запроса на сервере.

## Локальная разработка

```bash
npm install
npm run dev
```

Сайт по умолчанию: `http://127.0.0.1:3000` (см. `package.json`, скрипт `dev`).

Перед коммитом полезно проверить типы и линтер:

```bash
npx tsc --noEmit
npm run lint
```

## Деплой на gymacro.ru (Beget)

Продакшен собирается как **standalone**-приложение Node.js и выкладывается на хостинг Beget в каталог сайта. После распаковки перезапускается Passenger через файл `tmp/restart.txt`.

### Что нужно на машине, с которой деплоите

- Установленные **Node.js** и **npm**
- Доступ по **SSH** и **SCP** к аккаунту Beget (ключ или пароль настроены так, что команды `ssh` и `scp` выполняются без интерактива)
- На **Windows** обычно уже есть `tar` и OpenSSH Client; при ошибках при упаковке установите Git Bash или используйте WSL

### Настройка SSH и каталога на сервере

1. Скопируйте **`deploy.env.example`** в **`deploy.env`** в корне проекта (или создайте **`.env.deploy`** — тот же формат `KEY=value`; он уже попадает под игнор `.env*`).
2. Заполните минимум **`DEPLOY_SSH`** в виде `пользователь@хост` Beget (как для входа по SSH).
3. При необходимости задайте **`DEPLOY_REMOTE_DIR`** — каталог **`public_html`** вашего сайта на Beget (в примере указан путь вида `~/имя_аккаунта.beget.tech/public_html`).
4. Опционально: **`DEPLOY_REMOTE_ARCHIVE`** (куда кладётся архив после `scp`, по умолчанию `~/gymacro-deploy.tgz`), **`DEPLOY_ARCHIVE_NAME`** (имя локального `.tgz`).

Уже заданные в оболочке переменные **не перезаписываются** файлами. Если заданы и **`.env.deploy`**, и **`deploy.env`**, значения из **`deploy.env`** имеют приоритет для совпадающих ключей.

Файлы **`deploy.env`** и **`.env.deploy`** не коммитьте (секреты и индивидуальные пути).

### Одна команда — полный цикл

Из корня репозитория:

```bash
npm run deploy:beget
```

Скрипт **`scripts/deploy-beget.cjs`** выполняет:

1. **`npm run build`** — Next.js и копирование `public` и `.next/static` в standalone через **`scripts/prepare-standalone.js`**.
2. Создание архива (по умолчанию **`gymacro-deploy.tgz`** в корне репозитория): **`server.js`**, **`package.json`**, **`.htaccess`**, **`.next/standalone/`**.
3. Загрузка архива по **SCP** на Beget.
4. По **SSH**: распаковка в **`DEPLOY_REMOTE_DIR`**, создание **`tmp/restart.txt`** для перезапуска Passenger.

Отдельно для ручной упаковки без выгрузки можно использовать **`npm run deploy:pack`** (архив **`gymacro-deploy.tgz`** в корне репозитория для последующей ручной загрузки).

После успешного выполнения изменения должны быть видны на **https://gymacro.ru** (иногда с небольшой задержкой из‑за кэша или перезапуска).

### Windows и автоматический деплой

Скрипт **`deploy-beget.cjs`** на Windows запускает **`npm run build`** через оболочку (`shell: true`), иначе шаг «Сборка» может завершаться ошибкой без понятного вывода. Убедитесь, что в **`PATH`** доступны **`npm`** и **`tar`** (в сборках Windows 10/11 обычно уже есть).

### Passenger и каталог приложения

- Перезапуск Node после деплоя: **`mkdir -p tmp`** и **`touch tmp/restart.txt`** должны выполняться **в том же каталоге**, где лежит **`server.js`** после распаковки (часто корень **`public_html`**, если не используете подпапку для приложения).
- Если сайт не подхватил новый билд, попробуйте ещё раз **`touch tmp/restart.txt`** и обновите страницу с «жёсткой» перезагрузкой (Ctrl+F5).

### Если загружаете архив вручную (FTP / файловый менеджер)

1. Передача архива только в **бинарном** режиме (не ASCII): иначе **`gymacro-deploy.tgz`** приходит повреждённым.
2. На сервере в **`public_html`** перед **`tar -xzf`** проверьте целостность:
   ```bash
   gzip -t gymacro-deploy.tgz && echo OK
   ```
   Сообщение **`unexpected end of file`** / **`BROKEN`** означает битый файл — удалите архив на сервере, заново выполните **`npm run deploy:pack`** локально и залейте его снова.
3. Команда распаковки — **одной строкой**, без разрыва посередине имени файла:
   ```bash
   tar -xzf gymacro-deploy.tgz
   ```

### Ручные шаги (если не хотите использовать готовый скрипт)

```bash
npm run build
tar -caf gymacro-deploy.tgz server.js package.json .htaccess .next/standalone
scp gymacro-deploy.tgz USER@HOST:~/
ssh USER@HOST "tar -xzf ~/gymacro-deploy.tgz -C /path/to/public_html && mkdir -p /path/to/public_html/tmp && touch /path/to/public_html/tmp/restart.txt"
```

Команды `tar`/`scp`/`ssh` должны совпадать с вашей ОС и настройками хостинга.

### Частые проблемы

| Симптом | Что проверить |
|--------|----------------|
| **`scp` / `ssh`: Permission denied** | SSH-ключ или **`DEPLOY_SSH`** в **`deploy.env`**, вход без пароля в терминале |
| **`npm run deploy:beget`** обрывается на «Сборка» | Обновите Node/npm; на Windows не удаляйте **`shell: true`** для **`npm`** в **`deploy-beget.cjs`** |
| **`tar: Unexpected EOF`** на сервере | Перезалить **`.tgz`**, проверить **`gzip -t`** и размер файла (байты) локально и на сервере |
| Старый контент на сайте после деплоя | **`touch …/tmp/restart.txt`**, кэш ISR до ~1 ч на главной, Ctrl+F5 в браузере |

### Бэкапы на Beget

Перед рискованными правками на сервере используйте **резервное копирование** в панели хостинга. Имеет смысл убедиться, что в **автоматических** бэкапах попадает **база MySQL** (WordPress в **`/cms`**): только файловый архив без БД не восстановит контент CMS полностью.

### Публикация статей через mcp-kv (WordPress)

В личном кабинете [mcp-kv.ru](https://mcp-kv.ru) для WordPress укажите:

| Поле | Значение |
|------|----------|
| URL сайта | `https://gymacro.ru/cms` |
| REST API | `https://gymacro.ru/cms/wp-json/` |

**Не** подставляйте URL страницы профиля с паролями приложений (`…/wp-admin/profile.php`) — из‑за этого MCP стучится в `…/profile.php/wp-json/…` и получает редирект 302 на логин.

Для проверки откройте в браузере: `https://gymacro.ru/cms/wp-json/wp/v2/posts?per_page=1` — должен вернуться JSON, а не форма входа.

Авторизация — **Application Password** (Пользователи → Профиль → Пароли приложений) для учётной записи с правами редактора/администратора.

### Запуск standalone локально (проверка билда)

```bash
npm run build
npm start
```

Используется корневой **`server.js`**, который переходит в каталог standalone и запускает встроенный сервер Next.js.
